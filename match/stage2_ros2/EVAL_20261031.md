| 项 | 设置 |
|---|---|
| 主场景 | A 席我们的 Agent，B/C/D 全 `hybrid` |
| 局数/seed | 1000 局，seed 500000–500999 |
| 地图/出生 | `spawn=2` 随机出生，`rot=1`，`map=random` |

| 其他 | `strict=1`，`economy=1`，`dcap=1`，`contest=1` |
| 指标 | 前二率（主）、第一率、均分、平均排名；另看 D、reach、死亡、无效动作 |
| 基线 | `merged_orig` 原始 Agent + **同一个修正后的评测器** |
| 编译器 | MinGW g++ 4.9.2 (TDM64)，`-std=c++14 -O2` |

> 评测器修正：旧 `match4` 把潘潘易伤按“每次移动后 30 Tick”计算，且整个 30 Tick 都可触发；规则 §8.9 是“前 20 Tick 成功移动才触发，统一在事件生效后第 30 Tick 到期”。已修正，并用同一修正版评测器重建基线，避免把评测器差异算到 Bot 头上。

## 7. 建议

1. **保留这批修复**：主场景没有回归，事件密集场景略正向，且规则正确性更重要。
2. 若接下来只按“前二率”优化，下一轮应针对 **3hybrid 的资源/任务竞争**，而不是继续在事件边际上加码；本批事件修复的收益上限已经被 1000 局的噪声淹没。
3. 现场仍需在机器人上跑 `run_merged_tests.sh`，并做一次真实 LLM 延迟/配额联调；本报告的 `eventaware=1` 是离线真值注入，不包含 LLM 延迟。
4. 评测器已修正潘潘时序；以后和旧报告比较时，注意旧 `match4` 的 vulnerable 计时不同，不能直接混用。
